pgloom-engineering Intended Architecture

Autonomous engineering orchestration on top of pgloom runtime primitives.

Autonomy Boundary

  • • Human defines project and feature goals up front
  • • Agents own planning, QA, implementation, review, repair
  • • Human returns only for final PR judgment

Shared Runtime

  • • pgloom stores tasks, leases, events, and workflow state
  • • engineering tables store contracts, handoffs, recovery
  • • model and token usage are first-class evidence

Project Coupling

  • • Registry metadata controls write paths and gates
  • • Worktrees isolate QA and implementation attempts
  • • Deterministic validators guard model outputs
