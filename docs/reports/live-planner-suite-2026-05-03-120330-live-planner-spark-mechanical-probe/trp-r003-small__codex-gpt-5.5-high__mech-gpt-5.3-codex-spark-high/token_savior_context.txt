### [R-003] Crypto-domain config + diagnostics parity
- **Status:** TODO
- **Feature id:** null
- **Goal:** `/api/config/*` and `/api/diagnostics/*` return crypto-scoped runtime metadata instead of falling back to equities identifiers.
- **Scope:** Thread `?domain=crypto` through config + diagnostics controllers to the crypto runtime's live-config + partition state, expose per-domain `runtimeConfigVersion` + `graphId`, domain-correct venue list.
- **Out of scope:** New diagnostics endpoints, config mutation (read-only parity pass).
- **Acceptance:** Every config + diagnostics endpoint returns correct data for both `domain=equities` and `domain=crypto`, Playwright selector-switch covers both.
- **Depends on:** none.
- **Notes:** Crypto graph id today comes from `CryptoPartitionedRuntime` — thread that through instead of hardcoding the equities `runtimeConfigVersion`.

# DECISIONS relevant excerpt

**Decision:** Redis is the hot serving layer — latest snapshots, rankings, short time windows — written by `app-core` as projections from the runtime graph. A columnar time-series store is the canonical historical and replay store; replay feeds back into the graph for research workflows. `app-api` reads only from Redis and the historical store; it never writes to either.
**Consequences:** `app-api` is allocation-light and read-only. Any change that adds a DB write path in `app-api` or a direct historical-store read from the UI is a boundary violation and needs a new DECISIONS entry. Rules out adding Postgres / SQLite / Prisma / Drizzle as an OLTP layer — persistence is Redis + the historical store.
**Decision:** Adopt **QuestDB** (Apache 2.0) as the canonical historical store. Pair it with a date-partitioned **Apache Parquet lake** as the authoritative capture substrate and the research-notebook surface (DuckDB / Polars read from the lake directly). A background bulk-loader moves captured Parquet partitions into QuestDB for replay cursors and API historical reads.
**Context:** The event graph runtime is `dag-framework`, a sibling repo. Early in the project it was tempting to copy nodes into `platform-runtime` for quick iteration, which would fork the allocation invariants and the replay semantics.
**Decision:** `dag-framework` is a published GitHub-Packages dependency (`com.joshorig.ull.dag:...`), bumped via a coordinated upstream release. `platform-dsl` + `platform-runtime` + `platform-events` layer on top of it but never fork it. Breaking changes originate in `dag-framework` and propagate down.
**Consequences:** Any API change needed for trade-research-platform's graphs goes to `dag-framework` first. Pinning a local snapshot of dag-framework here is forbidden. Rules out "we'll patch dag-framework locally and upstream later" — those patches rot.
**Context:** The app has many routes and many data surfaces. Unit tests alone do not catch routing bugs, URL-param regressions, or proxy desync between the UI and `app-api`. End-to-end Playwright runs are the only way to know the cockpit actually works.
**Decision:** Vitest owns unit tests (28 files, including `api-contract-snapshots.test.ts` as the API contract gate). Playwright owns end-to-end across Chromium + WebKit + iPhone 13 profiles. The golden-path flow `"cockpit top opportunity launches backtest with the selected symbol"` is the one test that must never break.
