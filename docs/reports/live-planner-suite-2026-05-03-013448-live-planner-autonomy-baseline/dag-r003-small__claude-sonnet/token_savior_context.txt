# ROADMAP relevant entry

### [R-003] YAML graph topology loader
- **Status:** TODO
- **Feature id:** null
- **Goal:** Load a graph definition from `graph.yaml` at startup so non-Java operators can deploy pipeline changes without recompiling.
- **Scope:** `GraphYamlLoader.fromFile(Path)`, schema for nodes/edges/partitions/watermarks, validation against registered node catalog, error messages for unknown node types.
- **Out of scope:** Hot-reload of YAML (that's R-005), mutation via YAML edit, YAML schema versioning.
- **Acceptance:** Load test for a 5-node graph from YAML, compare loaded `CompiledPlan` to hand-built plan for byte equivalence, load-time < 100ms.
- **Depends on:** none.
- **Notes:** Load path is startup-only — no YAML parsing on hot paths, ever.

# DECISIONS relevant excerpt

_Architectural decisions with enough context that a future agent can tell whether a proposed change is undoing something load-bearing. Schema:_
**Consequences:** Any allocation introduced into the hot path (new, boxing, autoboxing, lambda capture allocations, non-reusable iterator creation, String concat) that exceeds 0.005 B/op fails CI. Rules out "we'll optimise it later" refactoring of hot paths. Agents implementing dag-framework nodes must include a `Check:` node in their BRAID graph for `jmhSmokeCheck` green before declaring `BRAID_OK`.
**Context:** Both are candidate low-latency messaging stacks. Chronicle Map/Queue is popular but has licensing friction for commercial use and a different allocation profile than Aeron IPC.
**Decision:** Use Aeron (IPC and shared-memory transport) for in-process and inter-process event transport. No Chronicle dependency anywhere. Aeron is currently only wired into `examples`, but the decision applies framework-wide when transport is added.
**Context:** `System.out.println` is synchronous, unbuffered, and allocates for every call. Logging on the hot path without guards allocates even at DEBUG-off because of varargs and boxing.
**Context:** The toolchain is pinned to Java 21 in every subproject's `build.gradle`. Trying to write Java 17 code "just in case" adds maintenance burden and defeats modern features (records, sealed types, pattern matching) that make zero-alloc code safer.
