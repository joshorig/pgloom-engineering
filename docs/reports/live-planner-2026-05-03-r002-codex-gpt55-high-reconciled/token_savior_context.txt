# DECISIONS relevant excerpt

## 2026-04-xx — Atomic GuaranteedPublisher (staged store+journal)
**Context:** Journal-write failures after a successful store write were leaving the system in a split state: the store had the new value but the journal didn't, which violated the per-key in-order at-least-once contract on replay.
**Decision:** Introduce `GuaranteedPublisher.publishChecked(...)` + `PublishResult` enum. The method stages the store write and journal append such that either both land or neither does. On journal-append failure the store write is aborted (not committed).
- Downstream consumers must handle `PublishResult.ABORTED` explicitly; implicit success is gone.
- Journal failure tests (`GuaranteedPublisherAtomicTest`) now enforce this invariant in conformance.
**Context:** `AeronReplayMergePoller` was updating the mmap lane position file on every advance but only forcing it to disk when callers explicitly configured flush knobs or reached `close()`. Resume tests passed in-process, but crash/restart durability still depended on a clean shutdown or relaxed CI timeouts.
- CI matrix simplified to a single JDK.
**Context:** The CI version-bump workflow has gone through multiple fix iterations. The current path is serviceable but carries patch-on-patch complexity that risks more churn the next time release automation changes.
